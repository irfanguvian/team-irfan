and the cap forces deleting something enforceable to fit something that isn't.

ITEM F: APPROVE
Reason: Every failure this addresses is already documented as real: unwired
ledger (README status), missing fixture deps (run-checks exits 2 on them),
stale `.tg-active`. A doctor script is zero-LLM, zero runtime cost, on-demand,
and sits on the rigid side of the table. To be checkable it must be hermetic:
it takes the settings path as an argument (defaulting to
`~/.claude/settings.json`) so run-checks can feed it synthetic fixtures instead
of the machine's real config. Scope is install health only — hook registration,
fixture node_modules present, ledger wiring probe (tmp cwd + marker + fake
payload → one ledger.log line), subagent-gate inert without marker, run-checks
pass count — not a re-implementation of run-checks.
Risk if implemented wrong: doctor reads only the live machine state and the
run-checks item becomes environment-dependent and flaky.
Required check: run-checks item: doctor against (a) a synthetic settings.json
with both hooks registered and the installed fixture → every line PASS, exit
0; (b) the same with the PostToolUse entry removed → a FAIL line naming the
ledger hook, exit non-zero.

ITEM G: REJECT
Reason: Architecturally incoherent. The router is not a spawned node —
graph.json lists it standalone ("the orchestrator itself") and router.md runs
as the main thread's own instructions, so the workflow cannot select a cheaper
model for triage; the main session's model is whatever the user runs. Getting
triage onto sonnet would require spawning a triage subagent: +1 Agent call on
every route, including HAND-BACK, whose entire value is costing ~1 call — and
this system's budget is denominated in tool calls, not model tokens, so the
proposal spends the measured currency to save an unmeasured one. The check-21
comment block in run-checks.sh already litigated and rejected splitting
router.md on exactly these grounds. The triage rubric is ~70 of router.md's
526 lines; compressing it changes nothing about which model reads it.
Risk if implemented wrong: a triage subagent becomes a second context that can
neither hold the HAND-BACK stop nor talk to Irfan, violating the star's
one-channel premise.
Required check: n/a — rejected.
